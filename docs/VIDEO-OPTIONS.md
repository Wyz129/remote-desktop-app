# 远程视频播放方案讨论

日期：2026-09-20。本文仅评估方案，本轮没有实现播放器、安装依赖或修改服务器。

成熟方案存在。当前应用使用 Electron 与 ssh2，建议先考虑 Video.js；若必须支持很多不同编码和容器，再评估 libVLC。

| 方案 | 成熟能力 | 与本应用的接入成本 |
| --- | --- | --- |
| [Video.js](https://github.com/videojs/video.js)，Apache-2.0 | 网页播放控件、字幕、倍速及流媒体播放 | 可嵌入虚拟桌面窗口；仍需把 SSH/SFTP 文件字节转换为受限媒体请求。解码能力取决于实际 Electron/Chromium，播放器库不会自行增加编码支持。 |
| [libVLC](https://www.videolan.org/vlc/libvlc.html)，LGPL-2.1 | 较广的格式、编解码和网络协议支持，适合原生嵌入 | 需要原生桥接、视频渲染与额外 DLL 分发。已有 SSH 实例的复用仍需设计，不能仅凭库支持 SFTP 就认为可复用当前连接。 |

推荐数据路径：服务器文件 → 现有 SSH/SFTP 连接 → 主进程受限媒体接口 → 隔离播放器 → 本地解码。主进程保管 SSH 凭据及远程路径，播放器只持有临时媒体标识。读取应支持字节范围、取消和有上限的缓存；播放器的 Range 请求需要正确映射到 SFTP 的 start/end，支持跳转并返回相应长度、范围与错误。

这种方式无需提前下载完整文件，也不要求服务器安装播放器。实际播放仍传输视频数据；完整观看的流量通常接近文件大小。跳转体验取决于网络延迟、视频索引、关键帧和缓存，需要实测。扩展名不能保证兼容性，首版应以实际打包 Electron 验证的编码组合为准。

遇到不兼容格式，可评估 [FFmpeg](https://ffmpeg.org/ffmpeg.html)：优先换封装，必要时才转码。服务器转码会增加 CPU/GPU 消耗；转码后的流与原文件的字节范围不同，跳转需要专门处理。FFmpeg 许可证取决于构建选项与组件，基础 LGPL 构建和启用 GPL 组件的分发要求不同。

[Plyr](https://github.com/sampotts/plyr) 也属于成熟 HTML5 播放器，但本次核验时其官方 README 已提示即将弃用并迁移至 Video.js，不建议作为新的接入首选。
